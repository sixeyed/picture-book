# Component 2 — `new-gig.ps1` Scaffolder

Turns a folder of full-res darktable exports into a ready-to-edit gig: copies the
files into `originals/<slug>/` and writes a `gigs/<slug>.json` stub with dimensions
filled in. The user then edits title/venue/description.

**Files:**
- Create: `scripts/new-gig.ps1`
- Create: `scripts/lib/read-dimensions.mjs` (tiny sharp wrapper the script shells to)

**Interfaces:**
- Consumes: content model rules from component 1 (slug pattern, stub shape).
- Produces: `originals/<slug>/*.jpg` and `gigs/<slug>.json` conforming to
  `schema/gig.schema.json`.

---

## 1. CLI

```powershell
./scripts/new-gig.ps1 -Source ~/exports/foundry-jun -Slug summer-festival-2026 `
    [-Title 'Summer Festival'] [-Date 2026-06-21] [-Venue 'The Foundry'] `
    [-Location 'Sheffield, UK'] [-Artists 'The Example Band','Support Act'] [-Force]
```

| Param | Required | Default |
|---|---|---|
| `-Source` | yes | — folder containing exported JPEGs |
| `-Slug` | yes | — validated against `^[a-z0-9]+(-[a-z0-9]+)*$` |
| `-Title` | no | slug converted to Title Case (`summer-festival-2026` → `Summer Festival 2026`) |
| `-Date` | no | today, ISO format |
| `-Venue`, `-Location` | no | `"TODO"` |
| `-Artists` | no | `@("TODO")` |
| `-Force` | no | overwrite an existing gig (re-copies files, regenerates JSON) |

## 2. Behaviour

1. `$ErrorActionPreference = 'Stop'`. Resolve repo root as `Split-Path $PSScriptRoot`.
2. Validate slug against the pattern; fail with a clear message otherwise.
3. Fail if `gigs/<slug>.json` or `originals/<slug>/` exists, unless `-Force`.
4. Enumerate `*.jpg` / `*.jpeg` (case-insensitive) in `-Source`, sorted by name.
   Fail if none. Warn (list, don't copy) any other file types found.
5. Copy files to `originals/<slug>/` preserving names.
6. Read dimensions for all files in one call:
   `node scripts/lib/read-dimensions.mjs originals/<slug>` → JSON on stdout.
7. Write `gigs/<slug>.json` (UTF-8, no BOM, 2-space indent, trailing newline):
   `$schema`, provided/defaulted metadata, `permission: "display-only"`,
   `description: ""`, `cover` = first file, `images` = one entry per file in name
   order with `width`/`height` filled.
8. Print a summary: image count, the path of the JSON file, and next steps
   ("edit title/venue/description, then run ./scripts/build.ps1").

Orientation from EXIF: use the **rotation-corrected** dimensions (sharp: swap
width/height when `metadata.orientation` is 5–8), so a portrait shot stored as
rotated-landscape gets portrait dimensions in the JSON.

## 3. `scripts/lib/read-dimensions.mjs`

```javascript
import { readdir } from "node:fs/promises";
import { join } from "node:path";
import sharp from "sharp";

const dir = process.argv[2];
if (!dir) { console.error("usage: node read-dimensions.mjs <dir>"); process.exit(1); }

const files = (await readdir(dir)).filter((f) => /\.jpe?g$/i.test(f)).sort();
const out = [];
for (const file of files) {
  const m = await sharp(join(dir, file)).metadata();
  const rotated = m.orientation >= 5;              // EXIF orientations 5-8 are 90°/270°
  out.push({
    file,
    width: rotated ? m.height : m.width,
    height: rotated ? m.width : m.height,
  });
}
process.stdout.write(JSON.stringify(out));
```

`new-gig.ps1` parses this with `ConvertFrom-Json` and builds the stub with
`ConvertTo-Json -Depth 5`. Note PowerShell's `ConvertTo-Json` escapes some
characters oddly but produces valid JSON; acceptable for a stub the user edits.

## 4. Stub output example

```json
{
  "$schema": "../schema/gig.schema.json",
  "slug": "summer-festival-2026",
  "title": "Summer Festival",
  "date": "2026-06-21",
  "venue": "TODO",
  "location": "TODO",
  "artists": ["TODO"],
  "permission": "display-only",
  "description": "",
  "cover": "P1000063.jpg",
  "images": [
    { "file": "P1000063.jpg", "width": 6000, "height": 4000 },
    { "file": "P1000075.jpg", "width": 4000, "height": 6000 }
  ]
}
```

`build.ps1` validation intentionally tolerates `"TODO"` values (they are non-empty
strings) — the site will render them, which is visible enough to prompt fixing.

## 5. Test plan

Runner: Pester (`Invoke-Pester scripts/new-gig.tests.ps1`), using a temp source dir
with two tiny JPEGs generated by sharp in a `BeforeAll` step
(`node -e "import('sharp').then(({default:s})=>s({create:{width:40,height:30,channels:3,background:'#333'}}).jpeg().toFile('a.jpg'))"`,
and one 30×40 portrait).

| Case | Expect |
|---|---|
| happy path | files copied; JSON exists; `images` has 2 entries in name order; portrait entry has `height > width`; `cover` = first file |
| resulting JSON | passes `validateGig` (call via `node -e` against `scripts/lib/gigs.mjs`) |
| slug `"Bad Slug"` | non-zero exit, no files written |
| existing slug without `-Force` | non-zero exit, existing files untouched |
| existing slug with `-Force` | JSON regenerated |
| source with zero JPEGs | non-zero exit |
| source containing `notes.txt` | warning printed, file not copied |

## 6. Acceptance criteria
